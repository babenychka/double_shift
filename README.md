# Double Shift

Утилита macOS для исправления текста, набранного в неверной раскладке, по двойному Shift. В строке меню отображается ⇧⇧. Исходная программа называется LayoutFixer: имя приложения и bundle ID `com.local.layoutfixer` сохранены для совместимости с существующими настройками.

## Установка

Нужны macOS 12+ и Command Line Tools. Полный Xcode не требуется.

Один раз установите инструменты Apple, если их ещё нет:

```bash
xcode-select --install
```

Дождитесь окончания установки. Создайте репозиторий GitHub, загрузите в его корень содержимое этой папки. Затем на каждом Mac выполните (замените OWNER на свой логин):

```bash
git clone https://github.com/OWNER/double-shift.git ~/double-shift
cd ~/double-shift
./install.sh
```

Установка без sudo. Приложение: `~/Applications/LayoutFixer.app`. Автозапуск создаётся через LaunchAgent. Папку клона нужно сохранить: из неё работают управление и обновления. Если раньше добавляли LayoutFixer вручную в Login Items, удалите старую запись, чтобы избежать двойного запуска.

При первом запуске разрешите **LayoutFixer** в **System Settings → Privacy & Security → Accessibility** и **Input Monitoring**, затем перезапустите:

```bash
~/.local/bin/double-shift restart
```

Разрешения macOS пользователь выдаёт вручную. После обновления с локальной ad-hoc подписью система может потребовать повторную выдачу: удалите старую запись приложения из разрешений, добавьте установленное приложение снова и перезапустите. Автоматически сбрасывать разрешения установщик не пытается.

Без автозапуска: `./install.sh --no-autostart` (при первой установке). Если автозапуск уже включён, выключите отдельной командой ниже.

## Обновление и управление

```bash
~/.local/bin/double-shift update
~/.local/bin/double-shift status
~/.local/bin/double-shift restart
~/.local/bin/double-shift autostart-off
~/.local/bin/double-shift autostart-on
~/.local/bin/double-shift rollback
~/.local/bin/double-shift uninstall
```

Можно добавить `~/.local/bin` в PATH и использовать просто `double-shift`.

`update` получает изменения текущей ветки через `git pull --ff-only`, собирает и устанавливает новую версию. Это обновление из исходников, а не скачивание GitHub Release. Нужен отдельный клон репозитория без незакоммиченных правок и с настроенной upstream-веткой. Приватные репозитории используют обычную авторизацию Git. Ошибка компиляции оставляет установленное приложение работающим. Предыдущая установленная версия сохраняется в `~/Applications/LayoutFixer.previous.zip`; `rollback` меняет версии местами. После отката следующая установка снова применит исходники текущего клона.

Настройки `defaults` сохраняются при установке, обновлении и удалении. Журналы: `~/Library/Logs/DoubleShift/`. Автообновления по расписанию нет: обновление запускается командой.

## Скорость преобразования

Выделенный текст сначала читается из активного поля; обход дерева Accessibility используется, только если поле не отдаёт выделение. В браузерах замена отправляется блоками до 20 кодовых единиц UTF-16, без посимвольного ввода. Буфер обмена не используется.

Для только что набранного слова чтение Accessibility пропускается. Удаление исходного слова по-прежнему выполняется клавишами Backspace, поэтому для длинных слов остаётся небольшая задержка.

## Разработка

- `Sources/main.swift` — исходный Swift-код из предоставленной инструкции.
- `Info.plist` — метаданные приложения.
- `VERSION` — версия в формате `1.2.3`.
- `scripts/build.sh` — сборка в `build/LayoutFixer.app`, без установки и запуска.
- `scripts/manage.sh` — установка, обновление, автозапуск и откат.

```bash
./scripts/build.sh
./install.sh
```

Установщик проверяет наличие `~/Applications/LayoutFixer.app` и выводит найденную версию. Затем собирает и проверяет подпись новой версии, останавливает приложение, сохраняет резервную копию в ZIP, удаляет старую установленную `.app` и устанавливает новую по тому же пути. Этапы выводятся в терминал и сохраняются в `~/Library/Logs/DoubleShift/install.log`. Другие копии за пределами этого пути установщик автоматически не удаляет. Хранится одна резервная версия. Это не транзакция, устойчивая к отключению питания; при прерванной установке проверьте папку `~/Applications`.

## GitHub и релизы

Содержимое этой папки должно находиться **в корне отдельного репозитория**. Рабочий процесс `.github/workflows/build.yml` собирает приложение для Apple Silicon и Intel и прикладывает ZIP и SHA-256 как артефакты Actions. На теге создаёт черновик GitHub Release, который можно проверить и опубликовать вручную.

Для новой версии измените `VERSION`, закоммитьте изменения и создайте совпадающий тег:

```bash
git add .
git commit -m "Release 1.0.1"
git push origin main
git tag v1.0.1
git push origin v1.0.1
```

Замените номер версии на актуальный. CI проверяет соответствие тега файлу VERSION.

Сборки подписываются ad-hoc, без Apple Developer ID и нотариализации. Скачанные ZIP могут блокироваться Gatekeeper; основной предусмотренный способ установки — локальная сборка из клона. Для распространения среди других пользователей стоит добавить Developer ID, нотариализацию и стабильную подпись. Локально можно указать `SIGN_IDENTITY='Developer ID Application: …' ./install.sh`, если сертификат уже установлен.
